# Signal — Fake News & Misinformation Intelligence

A local-development full-stack project for the Fake News & Misinformation Detection system. It separates model classification, related-article retrieval, analytics, and publisher-history scoring so the UI does not conflate a model prediction with verified truth.

## Stack

- **Frontend:** React, TypeScript, Vite, Recharts, Lucide
- **Backend:** FastAPI, Pydantic, pandas
- **Baseline model:** scikit-learn Pipeline with TF-IDF + Logistic Regression
- **Related-article retrieval:** TF-IDF cosine similarity over the local corpus (a transparent baseline; not a claim-verification system)
- **Persistence/artifacts:** local CSV + joblib + JSON files for this MVP

## Architecture and analysis behavior

- `frontend/src/App.tsx` is the React workspace entry for overview analytics, article analysis, publisher history, and batch reports. Article results keep the model prediction, contribution explanation, historical source score, and related corpus matches separate.
- `backend/app/main.py` exposes the FastAPI endpoints. The baseline model is loaded from `backend/artifacts/baseline_pipeline.joblib`; the existing TF-IDF vocabulary and classifier preprocessing are not changed by this application.
- `backend/app/services/model_service.py` reads the fitted class order and maps its probabilities and signed contributions to REAL/FAKE. Contributions are each submitted document's TF-IDF value multiplied by the fitted Logistic Regression coefficient. They describe model behavior, not factual support.
- The serving baseline remains TF-IDF + Logistic Regression. `backend/train_transformer.py` is an optional, separate Hugging Face fine-tuning/evaluation workflow; it does not replace the baseline or serve transformer predictions. It requires a local model directory and never downloads a model automatically.
- `backend/app/services/evidence_service.py` uses the fitted TF-IDF vectorizer and cosine similarity against the local evidence corpus. It returns up to the three highest-scoring matches and returns an empty list when no positive-similarity match or index is available. Matches are related labeled records, not verification or stance judgments; corpus dates are included only when present.
- `backend/app/services/analytics_service.py` computes distributions and trends from available labeled rows. It removes exact normalized title/body duplicates; rows with an identical text assigned conflicting labels are excluded from comparisons. It reports word count, exclamation marks, uppercase-letter percentage, Flesch Reading Ease, topic groups, and a two-sided Mann–Whitney U comparison of absolute VADER compound sentiment scores. The emotional-language comparison reports both sample sizes, medians, p-value, and rank-biserial effect size. The observations are not causal or truth evidence; statistical significance is not practical importance.
- Baseline training removes exact/conflicting duplicates, groups near-duplicate articles using character TF-IDF cosine similarity (threshold 0.90), and performs a stratified group split so detected groups stay within one partition. The report also includes held-out-source and chronological evaluations when fields and class distributions permit them. Source/time evaluations report eligible and missing row counts and return unavailable rather than infer missing values. These controls do not address every topic, source, event, or collection artifact; external evaluation is still required.

## Requirements

- Node.js 20+ and npm

## Run on Windows

### 1. Install backend dependencies

The release ZIP includes a trained baseline model, evaluation metadata, and evidence corpus, so the API can start without the original CSV files. Open a terminal in the `backend` directory:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. (Optional) Retrain the baseline

Copy `Fake.csv` and `True.csv` into `backend/data/`, then run:

```powershell
python train_model.py
```

Training generates:

- `artifacts/baseline_pipeline.joblib` — fitted TF-IDF + Logistic Regression pipeline and metadata
- `artifacts/evidence_corpus.csv` — corpus used for related-article retrieval
- `artifacts/model_metrics.json` — held-out evaluation metrics

Training can take several minutes and uses local CPU by default. Metrics are not guaranteed to generalize beyond this dataset. The Fake/True corpus may contain publisher, topic, date, and collection artifacts; even near-duplicate-aware, source-held-out, or chronological splits are not sufficient to prove real-world performance. Use external test data before production.

The checked-in `model_metrics.json` reports the previously measured 20,000-row random held-out evaluation: accuracy 0.988, FAKE precision 0.9909, recall 0.9850, F1 0.9880, ROC-AUC 0.9991, and confusion matrix `[[1982, 18], [30, 1970]]`. These are stored training-run results; the revised near-duplicate/source/time workflow has not been run, and its metrics must not be inferred from these older values.

### 3. Start the API

From `backend/` with the virtual environment active:

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

API docs: http://127.0.0.1:8000/docs
Health: http://127.0.0.1:8000/api/health

### 4. Start the frontend

Open a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the Vite URL shown in the terminal, usually http://localhost:5173.

For a different API URL, create `frontend/.env` with:

```text
VITE_API_URL=http://localhost:8000/api
```

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | API/model status |
| POST | `/api/predict` | Predict from title/text or attempt extraction from a URL |
| GET | `/api/analytics` | Dataset class, subject, date, and linguistic summaries |
| GET | `/api/sources` | Publisher leaderboard, when a valid history registry exists |
| POST | `/api/batch` | CSV predictions; returns downloadable CSV |

Example prediction request:

```json
{
  "title": "Example headline",
  "text": "Paste article text here. At least 30 characters are required."
}
```

Batch CSV should contain a `title` or `headline` column and/or a `text`, `article`, or `content` column.

## Source credibility registry

The supplied dataset has no publisher identity field. To enable the leaderboard, create `backend/data/publisher_history.csv` with these columns:

```csv
publisher,real_articles,fake_articles
Publisher name,120,8
```

Counts must come from documented, auditable records and a consistent labeling policy. The bundled `publisher_history.csv` rows are accepted as registry-provided historical labels, but this application does not independently verify their provenance. `publisher_history.example.csv` is schema-only; its sample values are illustrative and must not be presented as real publisher data.

The score preserves the existing Beta(2,2)-smoothed historical REAL-label share:

```text
((real_articles + 2) / (real_articles + fake_articles + 4)) * 100
```

An article-level score is returned only when the URL resolves to a registry domain and the source has at least 30 historical rows. Configure `SOURCE_MINIMUM_SAMPLE_SIZE` to another positive integer; the default is 30. Subdomains match their registered parent domain, but lookalike domains do not. Unknown sources and insufficient histories return an unavailable status, never a fallback zero. Source score does not alter model prediction or confidence.

## URL and CSV limits

Article extraction accepts public HTTP(S) URLs only. It rejects loopback, private, link-local, and other non-global IP addresses after DNS resolution; each redirect is validated before following it. Requests have connect/read timeouts and are limited to five redirects and 2 MiB of response content. URL extraction is best-effort; do not expose this development API publicly. Deployments with hostile DNS or network environments should additionally enforce outbound network policy at the host/container boundary.

CSV batch requests accept `.csv` files up to 5 MiB and 5,000 rows. Existing title/headline and text/article/content aliases and report columns are preserved. Empty or malformed uploads return a user-facing error.

## Optional Transformer Training

This separate workflow is for explicit local experimentation only. It does not change `baseline_pipeline.joblib`, the baseline prediction endpoint, or the baseline preprocessing. Install optional packages only if you intend to run it:

```powershell
cd backend
pip install -r requirements-transformer.txt
python train_transformer.py --model-path C:\models\distilbert-base-uncased --epochs 1 --max-length 256
```

`--model-path` must identify a model already present on disk. Remote model identifiers are rejected and Hugging Face loading uses `local_files_only=True`. The workflow uses `Fake.csv`/`True.csv`, or the existing labeled evidence corpus fallback, removes exact normalized duplicates, excludes conflicting-label duplicates, uses a reproducible stratified split, and writes the trained model to `artifacts/transformer/model` plus metrics to `artifacts/model_metrics_transformer.json`. The workflow has not been run as part of this verification. It reports accuracy, FAKE precision/recall/F1, confusion matrix, and ROC-AUC; near-duplicate and source/time leakage review is not implemented for the transformer workflow.

The transformer artifact is not connected to inference. Selecting it for production would require a separately designed model-selection API and model-specific explanations; baseline Logistic Regression contributions must not be used to explain transformer predictions.

## Current MVP boundaries

- Transformer fine-tuning is optional and training-only; the application continues to serve the baseline TF-IDF + Logistic Regression model.
- Explanations are linear-model feature contributions, not causal explanations.
- Evidence retrieval finds similar records from the local labeled corpus. Records are not independently verified and similarity does not mean support or contradiction. The app labels them accordingly.
- URL extraction is best-effort and can fail for JavaScript-rendered, paywalled, or bot-protected pages.
- Local development only: before public deployment, add authentication, rate limits, host-level outbound-network restrictions, logging controls, privacy handling, and production hosting configuration.
- This MVP uses local CSV/joblib artifacts, not a production database. PostgreSQL and a managed artifact store can be added when the schema and deployment environment are finalized.

## Suggested next development milestone

After the baseline web app is run and reviewed: improve data leakage evaluation, add verified publisher data, replace the similarity-only evidence panel with a traceable retrieval + stance-assessment pipeline, then benchmark a DistilBERT model against the baseline.
